## Фаза 0: Определение области ревью

Определи, что ревьюим:
- Конкретный файл или директорию (если указан путь)
- Последние изменения (если указан `--diff` или `--staged`)
- Весь модуль (если указано имя фичи в `app/` или общего модуля)

## Фаза 1: Загрузка контекста

## Фаза 2: Проверка по аспектам

Для каждого аспекта выдай оценку: OK / warning / critical.

### 2.1 Код стайл проекта

- [ ] Type hints на всех параметрах и возвращаемых значениях
- [ ] Один файл = одна ответственность
- [ ] Шапка файла по формату, комментарий над каждым классом и методом, inline-комментарии перед логическими блоками
- [ ] Комментарии отглагольными существительными, без капслока, разделителей-линий и ссылок на ТЗ
- [ ] Импорты: stdlib → third-party → internal, без `import *` и импортов внутри функций
- [ ] Никаких magic numbers и magic strings
- [ ] `__init__.py`: однострочный «Экспорт …» с `__all__` или полностью пустой
- [ ] Нейминг файлов и папок по правилам: `<feature>_handler.py`, `schemas/<feature>_schemas.py`, `services/<feature>_service.py`

### 2.2 Архитектура

- [ ] Хендлеры не содержат бизнес-логику (только вызов services + ответ) и try/except
- [ ] Services не импортируют из хендлеров — однонаправленная зависимость
- [ ] Фичи не импортируют друг друга; общее для нескольких фич — в корне `app/`
- [ ] Схемы и структуры данных — в `schemas/` своего модуля
- [ ] Ошибки сервисов — классы из `app/utils/service_errors.py` с текстом в `detail`
- [ ] Модели (`models/`) не содержат бизнес-логику
- [ ] Redis операции только через `app/redis/`
- [ ] Конфиг читается только из `app/config.py` (Pydantic Settings)
- [ ] Новые зависимости добавлены в `requirements.txt` с точной версией

### 2.3 База данных (Tortoise ORM)

- [ ] Нет N+1 запросов (использовать `prefetch_related`, `select_related`)
- [ ] Транзакции используются, где нужна атомарность
- [ ] Защита от дублей держится на ограничении в БД или блокировке, а не на SELECT перед INSERT
- [ ] Новые поля/модели имеют миграцию или обоснование её отсутствия
- [ ] Нет сырых SQL-запросов без параметризации (SQL injection)

### 2.4 Безопасность

- [ ] Нет SQL injection
- [ ] Нет command injection
- [ ] Валидация входных данных от пользователя
- [ ] Нет утечки токенов/секретов в логах, ответах и коммитах

### 2.5 Async/await

- [ ] Нет блокирующих операций в async контексте (синхронные I/O)
- [ ] `await` расставлен правильно (нет забытых coroutines)
- [ ] Нет race conditions при параллельных запросах

### 2.6 Обработка ошибок

- [ ] Ошибки не проглатываются молча
- [ ] Пользователь получает понятное сообщение при ошибке
- [ ] Критические ошибки логируются

### 2.7 Тесты

- [ ] Новая логика покрыта тестами, покрытие `app` — 100%
- [ ] Где есть БД — интеграционный тест на настоящей PostgreSQL, а не мок
- [ ] Имена тестов — русский комментарий над `def`, шапка в файле теста
