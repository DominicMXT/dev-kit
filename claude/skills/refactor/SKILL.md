# Рефакторинг: $ARGUMENTS

## Фаза 1: Загрузка контекста

- `CLAUDE.md` — структура, стек, env-переменные; к нему подключены общий кодстайл, `backend/devtools/CLAUDE.md` и `user_role.md`

1. Прочитай файлы в области рефакторинга
2. Найди все файлы, которые их импортируют (зависимости) — через Grep
3. Читай тела только тех символов, которые будешь менять

## Фаза 2: Анализ проблем

Проанализируй код по категориям:

### Code Smells
- Дублирование логики (DRY нарушения)
- Длинные методы (>30 строк)
- God-функции (делают слишком много)
- Magic numbers (числа без именованных констант)
- Мёртвый код (неиспользуемые импорты, функции, переменные)
- Чрезмерная вложенность (>3 уровня if/for/try)

### Нарушения код стайла
- Отсутствие type hints
- Отсутствие шапки файла, docstring, комментариев над классами и функциями
- Комментарии с глаголами, капслоком, разделителями-линиями (`# ======`) или ссылками на ТЗ
- Неправильный порядок импортов (stdlib → third-party → internal), импорты внутри функций
- Бизнес-логика в хендлерах вместо `services/`, try/except в хендлерах
- Нейминг файлов и папок не по правилам

### Нарушения архитектуры
- **Однонаправленность:** `services/` не импортируют из хендлеров
- **Слайсы:** фичи не импортируют друг друга; нужное двум и более фичам — в корне `app/`
- **Раскладка:** схемы и структуры данных — в `schemas/` своего модуля; утилиты и сервисы фичи — в её папках
- **Ошибки:** ошибки сервисов — классы из `app/utils/service_errors.py`
- **Redis:** операции только через `app/redis/`
- **Конфиг:** только через `app/config.py`

### Нарушения SOLID
- **S:** класс/функция делает больше одного
- **O:** изменение поведения требует модификации существующего кода
- **D:** прямые зависимости вместо инъекции/передачи параметров

## Фаза 3: План рефакторинга

Составь план и покажи пользователю. Формат:

```
## Анализ: [файл/область]

### Найденные проблемы

| # | Тип | Серьёзность | Описание | Где |
|---|-----|-------------|----------|-----|
| 1 | Code Smell | warning | ... | файл:строки |
| 2 | Архитектура | critical | ... | файл:строки |

### План рефакторинга

#### Шаг 1: [описание]
- Что: ...
- Почему: ...
- Файлы: ...
- Зависимые файлы (импортируют): ...
- Обратная совместимость: да / нет (описать)
- Риск: низкий / средний / высокий
```

Не пиши код, пока план не утверждён пользователем.

## Фаза 4: Выполнение (после утверждения)

### Порядок работы

1. Запиши план в `NEXT_SESSION.md`
2. Выполняй строго по плану, один шаг за раз
3. После каждого шага проверяй, что зависимые файлы не сломаны (Grep зависимостей)
4. Не меняй поведение — только структуру кода

### Ограничения

- Не трогай `requirements.txt` без явного указания (не добавлять пакеты)
- Не меняй модели и миграции без явного указания
- Сохраняй совместимость с текущим Docker-окружением

## Фаза 5: Валидация

1. Проверь, что импорты корректны во всех затронутых файлах
2. Линт: `./lint.sh`
3. Тесты: `./run_tests.sh`
4. Очисти `NEXT_SESSION.md`
